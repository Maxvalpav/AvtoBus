# Contributing

Спасибо, что хотите помочь AvtoBus! Ниже — как устроен проект и как вносить изменения.

## Кодекс поведения

Будьте уважительны. Люди приходят с разным опытом, и мы рады всем.
Нет токсичности, нет «это же очевидно».

## Как быстро стартовать

```bash
dotnet build                          # сборка решения
dotnet test tests/AvtoBus.Tests       # юнит-тесты ядра
dotnet test tests/AvtoBus.GeneratorTests  # тесты source generator
```

Требуется SDK .NET 10.

## Процесс

1. Форкните репозиторий, создайте ветку от `master`.
2. Внесите изменения. Отдельный логический шаг — отдельный коммит.
3. Добавьте тесты на новое поведение. Новый код без тестов не принимается.
4. Проверьте, что `dotnet build` и `dotnet test` зелёные.
5. Откройте Pull Request с описанием «что» и «зачем».

## Структура

- `src/AvtoBus.Core` — ядро: конверт, пайплайн, recoverability, метрики.
- `src/AvtoBus.InMemory` — in-memory транспорт и тест-харнесс.
- `src/AvtoBus.Generators` — source generator (netstandard2.0).
- `src/AvtoBus.Outbox.EfCore` — транзакционный outbox на EF Core.
- `src/AvtoBus.Sagas` — саги и durable execution.
- `src/AvtoBus.Testing` — харнесс: вся шина в памяти за одну строку.
- `docs/` — архитектура, 500 идей, реализации.

## Стиль

- File-scoped namespaces, nullable включены, net10.0.
- Комментарии на русском, документация XML на русском.
- Никаких секретов и подключений в коде.
- Следуйте `.editorconfig`.

## Правила коммитов

Абстрактный формат:

```
Идея 123: краткое описание изменения

Дополнительный контекст, если нужен.
```

## Тесты

- Юнит-тесты харнессом (`AvtoBusTestHarness`) — основа (идея 316).
- Ретраи/агрессивная восстановимость — через `FaultInjector`.
- Перф-чувствительные места — бенчмарки, а не просто «шёл быстрый» (идея 328).

## Вопросы

Открывайте issue с тегом `question`. Для быстрых вопросов — дискуссии.
