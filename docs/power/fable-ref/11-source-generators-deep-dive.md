# AvtoBus: deep dive в source generators и diagnostics

Этот документ полностью раскрывает compile-time модель AvtoBus: что генерируется, как работают incremental generators, полный каталог diagnostics, примеры generated code, AOT compliance и debugging.

## 1. Incremental source generators overview

AvtoBus использует Roslyn **incremental source generators** (`IIncrementalGenerator`). Они работают на этапе компиляции и не влияют на runtime.

### Как это работает

```csharp
// AvtoBus.SourceGeneration.HandlerGraphGenerator.cs
[Generator]
public sealed class HandlerGraphGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // 1. Находим все типы с handler-методами
        var handlerTypes = context.SyntaxProvider.CreateSyntaxProvider(
            predicate: static (node, _) => node is ClassDeclarationSyntax || node is StructDeclarationSyntax,
            transform: static (ctx, ct) =>
            {
                var typeDecl = (TypeDeclarationSyntax)ctx.Node;
                if (ctx.SemanticModel.GetDeclaredSymbol(typeDecl, ct) is not INamedTypeSymbol type)
                    return null;
                
                // Ищем методы Handle, HandleAsync, Consume, On
                var handlers = type.GetMembers()
                    .OfType<IMethodSymbol>()
                    .Where(m => m.Name is "Handle" or "HandleAsync" or "Consume" or "On")
                    .Where(m => m.IsStatic || !m.IsAbstract)
                    .ToArray();
                
                return handlers.Length > 0 ? (type, handlers) : null;
            })
            .Where(x => x is not null)
            .Collect();

        // 2. Генерируем код для каждого handler
        context.RegisterSourceOutput(handlerTypes, static (spc, handlerList) =>
        {
            foreach (var (type, handlers) in handlerList)
            {
                var source = GenerateHandlerCode(type, handlers);
                spc.AddSource($"{type.Name}_Generated.cs", source);
            }
        });

        // 3. Генерируем общий registry
        context.RegisterSourceOutput(handlerTypes, static (spc, handlerList) =>
        {
            var registry = GenerateRegistry(handlerList);
            spc.AddSource("AvtoBusHandlerRegistry.Generated.cs", registry);
        });
    }
}
```

### Что значит "incremental"

- Generator получает только changed syntax nodes, не весь compilation.
- При изменении одного handler — перегенерируется только его код.
- Общий registry перегенерируется только если изменилось количество handlers.

### Performance

- Incremental generators: ~10-50ms на project со 100+ handlers.
- Non-incremental (старый API): ~200-500ms.
- При изменении одного файла: только affected handlers.

```csharp
[AvtoHandler] // Атрибут для явной регистрации
public static class SubmitOrderHandler

        ShipOrder command,
        Order order,
        TimeProvider clock)
    {
        order.MarkShipped(command.TrackingNumber, clock.GetUtcNow());
        return new OrderShipped(order.Id, command.TrackingNumber, clock.GetUtcNow());
    }
}
```

## 3. EffectMapperGenerator: детальная логика mapping

### Mapping rules

1. **Tuple с named fields:**
   - `Reply`, `Response` → `AvtoEffects.Reply(...)`
   - `Event`, `PublishedEvent` → `AvtoEffects.Publish(...)`
   - `Command`, `SentCommand` → `AvtoEffects.Send(...)`
   - `Scheduled`, `Delayed` → `AvtoEffects.Schedule(...)`

2. **Tuple без named fields:**
   - Первый element → Reply (если тип совпадает с ICommand<T>.Reply)
   - Остальные → Publish (если реализуют IEvent) или Send (если реализуют ICommand)

3. **Single return value:**
   - Реализует `IEvent` → Publish
   - Реализует `ICommand<T>` → Reply
   - `void`/`ValueTask` → None

4. **AvtoEffects return:**
   - Прямо используется, никакого mapping.

### Generated mapper example

```csharp
// User code
public static (OrderAccepted Reply, OrderSubmitted Event) Handle(SubmitOrder cmd, ...)

// Generated mapper
private static AvtoEffects MapEffects_SubmitOrderHandler(
    (OrderAccepted Reply, OrderSubmitted Event) result)
{
    var effects = AvtoEffects.Empty;

    if (result.Reply is not null)
        effects = effects.Then(AvtoEffects.Reply(result.Reply));

    if (result.Event is not null)
        effects = effects.Then(AvtoEffects.Publish(result.Event));

    return effects;
}
```

### Ambiguous mapping → AVTO101 error

```csharp
// ERROR: два события в tuple без named fields
public static (OrderSubmitted, PaymentCaptured) Handle(...) //  AVTO101

// FIX: использовать AvtoEffects или named fields
public static AvtoEffects Handle(...) // ✅
public static (OrderSubmitted OrderSubmitted, PaymentCaptured PaymentCaptured) Handle(...) // ✅
```

```csharp
// OrderWorkflow_Runner.Generated.cs

internal sealed class OrderWorkflow_Runner : IAvtoWorkflowRunner
{
    public string WorkflowType => "OrderWorkflow";
    public Type WorkflowTypeClr => typeof(OrderWorkflow);

    public async Task<object?> ExecuteAsync(
        object input,
        IWorkflowContext context,
        AvtoWorkflowExecutionMode mode)
    {
        // Determinism guard: intercept TaskScheduler
        using var guard = AvtoWorkflowGuard.Enter(context);

        var workflow = new OrderWorkflow();

        try
        {
            return await workflow.RunAsync(
                (OrderWorkflowInput)input,
                context);
        }
        catch (AvtoNonDeterministicException ex)
        {
            // Non-deterministic API detected (Task.Delay, DateTime.UtcNow, etc.)
            context.Fault(ex);
            throw;
        }
        catch (Exception ex)
        {
            context.Fault(ex);
            throw;
        }
    }

    public async Task<object?> ReplayAsync(
        string workflowId,
        IReadOnlyList<WorkflowHistoryEvent> history)
    {
        // Replay from history for debugging
        var input = history
            .First(e => e.EventType == "WorkflowStarted")
            .Payload as OrderWorkflowInput;

        return await ExecuteAsync(input!, new ReplayContext(history), AvtoWorkflowExecutionMode.Replay);
    }
}
```

### Determinism guard implementation

```csharp
internal sealed class AvtoWorkflowGuard : IDisposable
{
    private static readonly AsyncLocal<IWorkflowContext?> CurrentContext = new();

    public static IDisposable Enter(IWorkflowContext context)
    {
        CurrentContext.Value = context;
        return new AvtoWorkflowGuard();
    }

    public void Dispose()
    {
        CurrentContext.Value = null;
    }

    // Called by analyzer-generated IL rewriting
    public static void ValidateDeterminism(object call)
    {
        var context = CurrentContext.Value;
        if (context is null) return; // Not in workflow context

        // Check for non-deterministic APIs
        if (call is Task task && task.IsCompleted)
        {
            // Task.Delay, Task.Run detected
            throw new AvtoNonDeterministicException(
                $"Non-deterministic Task detected: {call.GetType().Name}");
        }
    }
}
```

```csharp
// After (CodeFix)
public static ValueTask<OrderAccepted> Handle(SubmitOrder command, AppDbContext db, CancellationToken ct)
```

**AVTO104 Fix: Task → ValueTask**

```csharp
// Before
public static Task<OrderAccepted> Handle(...)

// After (CodeFix)
public static ValueTask<OrderAccepted> Handle(...)
```

**AVTO-WF001 Fix: Non-deterministic API**

```csharp
// Before
await Task.Delay(TimeSpan.FromMinutes(5), ct);
var now = DateTime.UtcNow;
var id = Guid.NewGuid();

// After (CodeFix)
await context.CreateTimer(TimeSpan.FromMinutes(5));
var now = context.Now;
var id = context.NewGuid();
```

### Enable generated files output

```xml
<PropertyGroup>
  <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>

```

Files appear in:

```
generated/
├── AvtoBus.SourceGeneration/
│   ├── SubmitOrderHandler_Generated.cs
│   ├── ShipOrderHandler_Generated.cs
│   ├── AvtoBusHandlerRegistry.Generated.cs
│   ├── AvtoBusDependencyResolver.Generated.cs
│   └── ...
└── AvtoBus.SchemaRegistry/
    ├── AvtoBusJsonSchemas.Generated.cs
    └── AvtoBusAsyncApi.Generated.cs
```

### Breakpoints в generated code

Generated code имеет `#line` directives, поэтому:

1. Breakpoint в user code работает нормально.
2. Breakpoint в generated code можно поставить через "Open Generated File" в IDE.
3. Stack trace показывает `SubmitOrderHandler_Generated.InvokeAsync`.

### Inspect generated code via CLI

```bash
dotnet avto handlers list
# Output:
# SubmitOrderHandler_Generated (message: ordershop.orders.submit)
# ShipOrderHandler_Generated (message: ordershop.orders.ship)
# ...

dotnet avto handlers inspect --name SubmitOrderHandler_Generated
# Shows generated source code
```

```xml
<PropertyGroup>

</PropertyGroup>
```

### Test infrastructure

```csharp
public static class CSharpGeneratorRunner
{
    public static GeneratorRunResult RunGenerator<TGenerator>(params string[] sources)
        where TGenerator : IIncrementalGenerator, new()
    {
        var syntaxTrees = sources.Select(s => CSharpSyntaxTree.ParseText(s)).ToArray();

        var references = AppDomain.CurrentDomain.GetAssemblies()
            .Where(a => !a.IsDynamic && !string.IsNullOrEmpty(a.Location))
            .Select(a => MetadataReference.CreateFromFile(a.Location))
            .Cast<MetadataReference>()
            .ToList();

        var compilation = CSharpCompilation.Create(
            "TestAssembly",
            syntaxTrees,
            references,
            new CSharpCompilationOptions(OutputKind.DynamicallyLinkedLibrary));

        var generator = new TGenerator();
        var driver = CSharpGeneratorDriver.Create(generator);

        driver = driver.RunGeneratorsAndUpdateCompilation(compilation, out var outputCompilation, out var diagnostics);

        return new GeneratorRunResult(
            GeneratedTrees: driver.GetRunResult().GeneratedTrees,
            Diagnostics: diagnostics.AddRange(outputCompilation.GetDiagnostics()));
    }
}

public record GeneratorRunResult(
    ImmutableArray<GeneratedSourceTree> GeneratedTrees,
    ImmutableArray<Diagnostic> Diagnostics);
```

## 13. Escape hatches

### Dynamic handlers (plugins)

```csharp
// Runtime-registered handler (not AOT-compatible)
bus.RegisterHandler("DynamicHandler", typeof(TestCommand), async (ctx, ct) =>
{
    // Dynamic logic
    return AvtoHandlerOutcome.Success(AvtoEffects.None);
});
```

Warning: `[RequiresDynamicCode]`, не работает в Native AOT.

### Dynamic routing (multi-tenant)

```csharp
bus.Routing(r => r.Dynamic(route =>
{
    var tenant = route.Context.TenantId;
    route.ToEndpoint($"orders.{tenant}.commands");
}));
```

Warning: Requires reflection at runtime, slower than static routing.

### Custom serializer (legacy formats)

```csharp
bus.Serialization(s => s
    .UseCustomSerializer<LegacyXmlSerializer>());
```

Warning: XML serialization не AOT-compatible из коробки.

## 14. Summary: что даёт source generation

- **Скорость**: 3-5x быстрее reflection-based dispatch.
- **Allocations**: 4x меньше heap allocations.
- **AOT**: Full Native AOT support, no reflection in hot path.
- **Diagnostics**: 40+ compile-time checks, CodeFixProvider.
- **Developer experience**: Generated code виден в IDE, breakpoints работают.
- **Maintainability**: Convention-based, меньше boilerplate.

Trade-offs:

- Build time: +10-15% на project с 100+ handlers.
- Debug complexity: нужно понимать generated code при проблемах.
- Generator updates = rebuild всего проекта.
