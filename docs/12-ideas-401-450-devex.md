# 💡 Идеи 401–450: DevEx, тулинг, Source Generators, CLI

### 401. `dotnet new avtobus-worker` — шаблоны проектов
Worker, WebApi+bus, Saga-service, Projection-service — с тестами, Dockerfile, compose, OTel — «правильно по умолчанию».

### 402. CLI `avtobus` — единый инструмент
`topology|dlq|saga|projections|contracts|schema|bench|dev|doctor` — всё, что упоминалось в идеях, в одном dotnet tool.

### 403. `avtobus doctor` — диагностика окружения
Проверки: соединение с брокером, права, версии, наличие outbox-таблиц, дрейф топологии, часы (NTP skew!) — со ссылками на фиксы.

### 404. Анализаторы Roslyn как продукт
Пакет `AvtoBus.Analyzers`: 30+ правил (AVB001–AVB0xx) с code-fix-ами: «Publish команды → заменить на Send», «мутабельный контракт → сделать record».

### 405. Code-fix «создай хендлер»
`bus.Send(new DoThing())` без хендлера → лампочка: сгенерировать класс хендлера с правильным неймингом и тестом.

### 406. Генерация тестов из подписей хендлеров
`avtobus scaffold tests` — по каждому хендлеру: скелет happy-path + idempotency + failure-тестов на харнессе.

### 407. Hot reload хендлеров
`dotnet watch` + перегенерация диспетчеров: правка хендлера применяется без рестарта воркера (metadata update friendly код генератора).

### 408. REPL шины: `avtobus repl`
Интерактив: `send PlaceOrder {orderId: "..."}`, `peek orders`, `drain orders.error --count 5` — C#-скриптинг с подключённым IBus.

### 409. Плейграунд сообщений в дашборде
Форма из JSON Schema контракта → отправка тестового сообщения из UI (только non-prod окружения, с аудитом).

### 410. Полная документация «5 минут до первого сообщения»
Бенчмарк DX: новый разработчик от `dotnet new` до обработанного сообщения — за 5 минут; CI-джоб реально прогоняет tutorial по шагам.

### 411. Рецепты миграции с конкурентов
`avtobus migrate masstransit|nservicebus|cap|rebus scan` — анализ проекта, отчёт соответствий API, авто-переписывание простых случаев (Roslyn codemod).

### 412. Слой совместимости MassTransit-контрактов
Понимаем `urn:message:` типы и конверт MassTransit — параллельная работа во время миграции.

### 413. Дизайн-документы ADR в репозитории
Каждое серьёзное решение — ADR в `docs/adr/`; культура открытой аргументации (как у Wolverine/Marten).

### 414. Публичный roadmap + RFC-процесс
Фичи проходят через RFC-issues с шаблоном; сообщество влияет на дизайн до кода.

### 415. Стабильные точки расширения с контрактными тестами
`ITransport`, `ISerializer`, `ISagaStore`, `IOutboxStore` — семверсия отдельно от ядра; conformance-kit для авторов плагинов (идея 98).

### 416. `AvtoBus.Extensions.*` — куратор community-пакетов
Реестр проверенных расширений с бейджами «проходит conformance», витрина в доках.

### 417. Понятные исключения с кодами и ссылками
`AvtoBusException [AVB-E042]: очередь 'orders' не существует. Возможные причины... Подробнее: avtobus.dev/e/AVB-E042` — каждая ошибка = страница документации.

### 418. First-run experience
Первый запуск без конфигурации → дружелюбный вывод: что поднято (InMemory), какие хендлеры найдены, ссылка на дашборд — как у Aspire.

### 419. .NET Aspire интеграция
`builder.AddAvtoBus()` в AppHost: ресурсы брокера, дашборд в Aspire Dashboard, service discovery строк подключения.

### 420. Конфиг-визард: `avtobus init`
Интерактивные вопросы (брокер? outbox? саги?) → генерация кода конфигурации с комментариями-объяснениями каждого решения.

### 421. Валидация конфигурации при старте с полным отчётом
Все ошибки конфига сразу списком (не по одной), с подсказками; `--dry-run` режим проверки без старта.

### 422. Справочник паттернов в документации
Каждый EDA-паттерн (Outbox, Saga, Claim Check, ECST...) — страница: проблема → решение → код на AvtoBus → грабли (стиль microservices.io + практика).

### 423. Учебный курс в репозитории
`samples/journey/01-hello ... 12-event-sourcing` — последовательные уроки, каждый собирается и тестируется в CI.

### 424. Интерактивные примеры в браузере
Blazor WASM песочница на сайте: правишь хендлер — видишь поток сообщений (InMemory транспорт в браузере!).

### 425. Генератор диаграмм последовательности из тестов
Тест харнесса → Mermaid sequence diagram фактического потока сообщений → автоматически в PR-комментарий (визуальный код-ревью потоков).

### 426. `avtobus explain <type>` — кто, что, куда
По типу сообщения: кто публикует, кто слушает, маршруты, ретраи, SLA — из compile-time модели + рантайм-каталога.

### 427. Импорт/экспорт «проводки» как код
Вся топология и маршруты сериализуются в YAML — ревью инфраструктурных изменений в PR (GitOps для шины).

### 428. Расширение для VS/Rider/VS Code
Подсветка хендлеров, CodeLens «3 паблишера / 2 подписчика», переход publish→handler (навигация по сообщениям как по методам).

### 429. Валидация DI-графа хендлеров на компиляции
Генератор знает зависимости хендлеров → отсутствие регистрации сервиса — предупреждение на build, не exception в проде.

### 430. Матрица поддержки версий прозрачно
Док-страница: .NET 10 LTS / .NET 11 STS, какие транспорты в каких версиях; политика breaking changes (semver честный).

### 431. Модульный монолит-стартер
Шаблон: modules/, контракты между модулями через шину InMemory, готовые швы для выноса модуля в сервис (Modulith-путь).

### 432. Генерация «шва» выноса модуля
`avtobus extract-module Billing` — создаёт проект сервиса, переносит хендлеры, переключает маршруты с InMemory на брокер, генерит миграционный план.

### 433. Встроенный линтер нейминга событий
Конвенции: события в прошедшем времени (`OrderPlaced`, не `PlaceOrderEvent`), команды в императиве; авто-fix.

### 434. Спецификация поведения как документация
Given/When/Then тесты харнесса экспортируются в живую спецификацию (markdown) — «что делает система» для аналитиков.

### 435. Демо-данные одной командой
`avtobus dev seed --scenario black-friday` — реалистичный поток событий для разработки UI/дашбордов.

### 436. Обратная связь производительности в IDE
Анализатор подсказывает: «хендлер делает 3 await-а в цикле по batch — рассмотрите BulkWrite» (эвристики из бенчмарков).

### 437. Стандартные заготовки middleware
Готовые: RateLimit, Deduplicate, Enrich, TenantResolve, FeatureFlag, AuditLog, Encrypt — подключаются строкой, исходники — учебные примеры.

### 438. Doc-тесты: код в доках компилируется
Все сниппеты документации извлекаются и собираются в CI (как rustdoc) — доки не устаревают.

### 439. Чейнджлог, понятный людям
Каждый релиз: «что нового» с примерами кода, «что сломалось» с миграционными сниппетами; `avtobus upgrade-check` сканирует проект на затронутые API.

### 440. Телеметрия фреймворка (opt-in, прозрачная)
Анонимная статистика фич (как dotnet CLI) — данные для приоритизации; полный опт-аут, публичный отчёт.

### 441. Официальные Docker-образы воркеров
`avtobus/worker-base`: chiseled, non-root, OTel-агент, healthcheck-ready — FROM и вперёд.

### 442. GitHub Actions / GitLab CI готовые пайплайны
Шаблоны: build+test+schema-check+topology-verify+bench-gate — скопировал и работает.

### 443. Публичный «зоопарк граблей»
Раздел доков: реальные инциденты EDA (анонимные) и как AvtoBus-фичи их предотвращают — продаёт правильные практики.

### 444. Стажёрский режим API
`bus.StrictMode()` — выключает все «магии» (авто-каскады, авто-топология): всё явно; для команд, которые хотят полный контроль и обучения.

### 445. Локализация диагностик
Сообщения анализаторов/ошибок RU/EN (культура из окружения) — снижаем порог входа.

### 446. Бот-помощник по кодовой базе документации
Индекс доков → LLM-поиск на сайте: «как сделать retry только для HttpRequestException» → точный сниппет (RAG по докам, без выдумок — ссылки обязательны).

### 447. Скрипт миграции контрактов между brokers-схемами
`avtobus schema sync --from confluent --to apicurio` — перенос реестра при смене вендора.

### 448. Пример «эталонная архитектура» e-commerce
Полный опенсорс-пример: 6 сервисов, саги, ES, проекции, дашборды, нагрузочные тесты — «как надо» одним репозиторием (как eShopOnContainers, но EDA-first).

### 449. Совместимость с Dapr как транспортом
AvtoBus поверх Dapr pub/sub building block — для команд, уже вложившихся в Dapr, наш DX + их инфраструктура.

### 450. Программа сертификации подключаемых транспортов
Бейдж «AvtoBus Certified»: прошёл conformance (98), бенч-минимумы (390), докам соответствует — доверие экосистеме.
