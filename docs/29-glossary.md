# 📖 Глоссарий: расшифровка всех терминов

> **Статус: Reference.** Термины относятся к целевой архитектуре и могут описывать ещё не реализованное поведение.

Все аббревиатуры и понятия документации простым языком.

---

## 1. Базовые понятия

| Термин | Что это |
|---|---|
| **AvtoBus** | Название фреймворка. «Автобус» (везёт сообщения по маршрутам) + «bus» (шина сообщений) |
| **EDA** | **E**vent-**D**riven **A**rchitecture — событийно-ориентированная архитектура: сервисы общаются сообщениями, а не прямыми вызовами |
| **Шина (Bus)** | Абстракция: кидаешь сообщение «в шину», она сама решает, кому доставить |
| **Брокер** | Внешняя система хранения/доставки: RabbitMQ, Kafka, NATS |
| **Команда (Command)** | «Сделай»: `PlaceOrder`. Ровно **один** получатель. Метод `Send` |
| **Событие (Event)** | «Произошло»: `OrderPlaced`. **0..N** получателей. Метод `Publish` |
| **Контракт** | C#-тип сообщения (`record`), который знают отправитель и получатель |
| **Хендлер (Handler/Consumer)** | Метод или класс, реагирующий на сообщение |
| **Envelope (Конверт)** | Обёртка вокруг тела: id, время, заголовки, трассировка |
| **Payload / Body** | Сами данные в сериализованном виде (байты) |
| **Топик (Topic)** | Канал для событий, много подписчиков |
| **Очередь (Queue)** | Канал для команд, один логический получатель |
| **Топология** | Вся структура очередей, топиков и связей в брокере |

## 2. Паттерны

| Термин | Что это |
|---|---|
| **Outbox** | Таблица исходящих в **твоей** БД. Данные и сообщение — в одной транзакции; фон отправляет в брокер. Лечит «данные сохранились, событие не ушло» |
| **Inbox** | Таблица обработанных. Дубликат видим по id и пропускаем |
| **Relay** | Фоновый процесс, читающий outbox и отправляющий в брокер |
| **Сага** | Долгий бизнес-процесс из шагов с состоянием: заказ → оплата → доставка |
| **Компенсация** | «Отменить сделанное»: забронировал → отменить. Замена rollback в распределёнке |
| **Оркестрация** | Есть «дирижёр» (сага), командующий шагами |
| **Хореография** | Дирижёра нет: каждый слушает события и решает сам |
| **Routing Slip** | Список шагов едет **внутри** сообщения; каждый сервис делает свой шаг |
| **Event Sourcing (ES)** | Хранить не состояние, а список событий. Состояние = «проиграть» события |
| **CQRS** | **C**ommand **Q**uery **R**esponsibility **S**egregation — разделение записи и чтения |
| **Агрегат** | Единица консистентности (DDD): `Order` со всеми правилами внутри |
| **Проекция (Read-model)** | Таблица для чтения, построенная из потока событий |
| **Snapshot** | Сохранённое состояние на версии N, чтобы не проигрывать 10 000 событий |
| **Upcaster** | Функция «событие v1 → v2». Меняем схему, не переписывая историю |
| **Claim Check** | Тело > 1 МБ → в S3, в брокер только ссылка |
| **DLQ** | **D**ead **L**etter **Q**ueue — очередь необработанных сообщений |
| **Poison message** | Сообщение, которое всегда падает (битый формат) — в отдельную очередь |
| **Идемпотентность** | Повторный вызов не меняет результат. Обработали дважды = как один раз |
| **Back-pressure** | Потребитель говорит «притормози» — защита от переполнения памяти |
| **Circuit Breaker** | Предохранитель: много ошибок → перестаём пытаться, ждём восстановления |
| **Bulkhead** | Переборка (как на корабле): сломался отсек — остальные держатся |
| **Correlation ID** | Общий id всей цепочки одного бизнес-сценария |
| **Causation ID** | Id сообщения-родителя. Даёт дерево причин |
| **Fan-out** | Одно событие → много подписчиков |
| **Partition Key** | Поле, по которому делим поток, чтобы сообщения одного клиента шли по порядку |
| **Consumer Group** | Реплики сервиса делят поток так, чтобы каждое сообщение обработалось один раз |
| **Log Compaction** | Хранить только последнее значение по каждому ключу |
| **ECST** | **E**vent-**C**arried **S**tate **T**ransfer — событие несёт полное состояние, а не только id |

## 3. Семантики доставки

| Термин | Смысл |
|---|---|
| **At-most-once** | Может потеряться, но не задвоится. Быстро, для метрик |
| **At-least-once** | Не потеряется, может прийти дважды. **Дефолт AvtoBus** |
| **Exactly-once** | Ровно раз. Честно возможно только внутри одной системы (Kafka-транзакции) |
| **Effectively-once** | At-least-once + дедупликация Inbox = как будто ровно раз |
| **Ack / Nack** | Подтверждение / отказ. Ack = «удали», Nack = «верни или в DLQ» |
| **Prefetch** | Сколько сообщений консьюмер берёт «в руки» заранее |
| **Visibility timeout / Lock** | Время, на которое сообщение скрыто от других, пока обрабатывают |
| **Redelivery** | Повторная доставка после Nack или таймаута |

## 4. Коды диагностик AVB***

`AVB` = **AV**to**B**us. Ошибки и предупреждения **в IDE при компиляции**.

| Код | Уровень | Значение |
|---|---|---|
| **AVB001** | Error | Команда отправляется, обработчика нет |
| **AVB002** | Error | У команды больше одного обработчика |
| **AVB003** | Warning | Событие публикуется, никто не подписан |
| **AVB010** | Warning | Контракт мутабельный — используй `record` с `init` |
| **AVB011** | Error | Контракт ссылается на доменный тип |
| **AVB015** | Warning | Денежное поле без валюты — используй `Money` |
| **AVB017** | Error | `TenantId` в теле контракта (должен быть в конверте) |
| **AVB020** | Error | Переиспользовано имя удалённого поля |
| **AVB021** | Warning | Сообщение > 64 КБ — рассмотри Claim Check |
| **AVB022** | Info | Событие-«свалка» (30+ полей) — стоит разбить |
| **AVB030** | Runtime | Цикл сообщений (ping-pong) |
| **AVB040** | Warning | Сага ходит в чужой сервис за данными |
| **AVB041** | Warning | Внешний шаг саги без таймаута |
| **AVB050** | Error | Агрегат загружает другой агрегат напрямую |

## 10. Три схемы простыми словами

### Outbox — почему без него ломается

```
❌ ПЛОХО:
  сохранить заказ в БД        ✅
  отправить событие в брокер  ❌ сеть упала
  → заказ есть, никто не знает. Данные разошлись.

✅ ХОРОШО (Outbox):
  ОДНА транзакция:
    сохранить заказ            ✅
    записать событие в таблицу ✅
  коммит
  → relay заберёт и отправит, когда сеть починится
```

### Inbox — почему дубли не страшны

```
Брокер гарантирует «не менее одного раза» → дубли неизбежны.

  пришло сообщение id=42
  вставляем id=42 в таблицу inbox
    ├─ вставилось     → обрабатываем
    └─ конфликт       → дубль, подтверждаем и уходим
```

### Сага — как откатить неоткатываемое

```
Забронировать отель  ✅ → компенсация: отменить бронь
Забронировать рейс   ✅ → компенсация: вернуть билет
Списать деньги       ❌ упало

→ компенсации в ОБРАТНОМ порядке:
   вернуть билет → отменить бронь → заказ отменён
```
